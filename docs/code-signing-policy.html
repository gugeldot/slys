Code signing policy

How the Windows builds of SLYS are signed, and what is never signed.

Provider

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Status: the application to the SignPath Foundation is in progress. Until it is approved, the Windows installer is not signed, and Windows may show a SmartScreen or Smart App Control warning. This page describes the policy that will apply from the first signed release.

What is signed

  • The Windows installer (Slys_Installer.exe) and the program files inside it, built from the public repository github.com/gugeldot/slys.
  • Only builds produced by the project's public GitHub Actions release workflow, from a tagged commit. Nothing is signed from a developer's computer.
  • Only the project's own code and its open-source dependencies, under the GPL-3.0-or-later licence. No other software is signed with this certificate.

Roles

  • Author, reviewer and approver: Gugeldot (github.com/gugeldot), the only maintainer. Each signing request is approved manually by the maintainer, and the account uses two-factor authentication.

Privacy

SLYS does not connect to the network and does not collect or send any data. The Flatpak build has no network permission at all.

Verifying a release

Every release publishes a SHA256SUMS file and a build attestation (gh attestation verify <file> --repo gugeldot/slys) that tie each file to the commit and the workflow that built it.
