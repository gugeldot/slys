# Development

## Layout

```
crates/slys-core     the whole product logic (Rust library): formats, crypto, fragment/recompose,
                     seed vault, inactivity wipe, versioning. No UI, no FFI.
crates/slys-cli      `slys` command line: test and script the core without the app
crates/slys-bridge   flutter_rust_bridge glue: thin, forwards to slys-core
app/                 Flutter app (Linux, Windows; macOS scaffold kept)
app/rust_builder     cargokit: builds slys-bridge as part of `flutter build`
packaging/           Inno Setup (Windows), Flatpak (Linux), icons
scripts/             version tooling, checksums, CLI demo
docs/                format specification, design notes
```

The app and the core are **one program**: `flutter build` compiles the Rust bridge into a shared
library that Flutter loads through FFI. There is no separate backend executable.

## Setup

* Rust through **rustup** (cargokit calls `rustup`; a distro-packaged Rust alone is not enough).
* Flutter (stable).
* Linux: `clang cmake ninja-build pkg-config libgtk-3-dev` (and `xvfb` for the app tests).
* Bridge generator: `cargo install flutter_rust_bridge_codegen --version 2.13.0 --locked`
  (the version must match `flutter_rust_bridge` in `app/pubspec.yaml` and the bridge crate).

## The fast loop ("real time")

| I am changing... | Do this | You see it... |
|---|---|---|
| Dart UI | `make dev` (hot reload) | instantly |
| Rust core logic | `cargo test -p slys-core` (or `cargo watch -x test` if installed) | in under a second for logic tests |
| The Rust API the app calls | `make watch-bridge` in one terminal and `make dev` in another | regenerates the Dart bindings on save; restart the app |
| The core by hand, without a UI | `make cli-demo`, or `slys frag/compose/inspect/seeds` | immediately |

Useful CLI facts:

* Passwords are never accepted as arguments. Use the prompt, `--password-stdin`, or
  `SLYS_PASSWORD=...` (handy in scripts).
* `SLYS_FAST_KDF=1` makes Argon2 cheap so manual tests are instant. **Never use it for real data.**
* `SLYS_CONFIG_DIR=/some/dir` moves the seed list, so experiments do not touch your real one.
  This also works for the app.

## Tests

* `cargo test --workspace`: unit tests, round trips in every mode, tamper/swap/truncation
  detection, v1 compatibility with vectors generated by the real 1.5.1 backend.
* `make test-app`: Flutter integration tests under xvfb. They run the **real Rust core through
  the real FFI bridge** (fragment, wrong password, rebuild) and build the real UI.

## Changing the Rust API

1. Edit `crates/slys-bridge/src/api/*.rs`.
2. `make bridge` regenerates `app/lib/src/rust/*` and `crates/slys-bridge/src/frb_generated.rs`.
   Both are committed; CI fails if they are out of date.

## Versioning

The workspace version in `Cargo.toml` is the single source of truth. `scripts/set-version.sh
X.Y.Z` updates it and `app/pubspec.yaml`; `scripts/check-version.sh` (run by CI) verifies that
`Cargo.toml`, `pubspec.yaml` and the newest `<release>` in the metainfo agree. The Inno Setup
script takes the version from the command line, the About screen reads it from the core, and the
git commit is embedded at build time (`SLYS_GIT_COMMIT` overrides it for tarball builds).
